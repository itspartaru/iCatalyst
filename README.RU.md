# Image Catalyst

Оптимизация / сжатие изображений PNG, JPEG и GIF без потери качества для **Windows и Linux**.

|![Adobe Photoshop](https://cloud.githubusercontent.com/assets/3890881/12113971/831d0e22-b3b7-11e5-8f6d-a5cc8f993767.png)|![Image Catalyst](https://cloud.githubusercontent.com/assets/3890881/12110952/70ce4462-b3a2-11e5-8b29-a3822b246dfe.png)|
|:----------|:----------|
|Adobe Photoshop CC 2015 (Экспортировать как) — 56,10 КБ|Image Catalyst (Xtreme) — 51,25 КБ|

Авторы — [**Lorents**](https://github.com/lorents17) & [**Res2001**](https://github.com/res2001)

> **Версия 3.0 переписана.** Управляющая часть переехала с пакетного сценария
> Windows в 1300 строк на ядро на Python 3. Именно это делает возможной работу
> под Linux и закрывает давний баг, из-за которого файлы с национальными
> символами в именах молча пропускались. Версия 2.7 осталась в репозитории и
> продолжает работать — см. [Переход с 2.7](#переход-с-27).

### Инструменты

Image Catalyst ничего не сжимает сам — он управляет известными оптимизаторами и
оставляет наименьший результат. Команда `icatalyst --doctor` показывает, какие из
них найдены на вашей машине, и точные команды, которые будут выполнены.

##### PNG:
- [oxipng](https://github.com/oxipng/oxipng), [OptiPNG](https://optipng.sourceforge.net/), [Zopfli](https://github.com/google/zopfli) (`zopflipng`), AdvDef ([AdvanceComp](https://github.com/amadvance/advancecomp))
- под Windows дополнительно: [TruePNG](http://x128.ho.ua/pngutils.html) 0.6.2.2, DeflOpt 2.07, [PNGWolfZopfli](https://github.com/jibsen/pngwolf-zopfli)

##### JPEG:
- JPEGTran из [MozJPEG](https://github.com/mozilla/mozjpeg) либо из [libjpeg-turbo](https://libjpeg-turbo.org/)

##### GIF:
- [GIFSicle](https://github.com/kohler/gifsicle)

### Системные требования

- **Windows 10 и выше.** Готовой сборке `iCatalyst.exe` больше ничего не нужно.
  Для запуска из исходников нужен Python 3.9 или новее.
  *(Версия 2.7 работала на Windows XP SP3; 3.0 — нет, потому что там не работает Python 3.9.)*
- **Linux**: Python 3.9 или новее и сами оптимизаторы:
  ```
  sudo apt install optipng zopfli advancecomp gifsicle libjpeg-turbo-progs
  make tools          # скачает oxipng, сверив его SHA-256
  ```
  `make apt` печатает готовую строку установки, а `make check` говорит, чего не
  хватает и чем именно это обойдётся.

### Drag and Drop

![Drag and Drop](https://cloud.githubusercontent.com/assets/3890881/7943598/28496fd4-096e-11e5-8df6-d6415e47caf8.png)

- **Windows**: бросайте папки или файлы на `iCatalyst.exe`, а при запуске из
  исходников — на `iCatalyst-3.bat`.
- **Linux**: установите `icatalyst.desktop` (`cp icatalyst.desktop
  ~/.local/share/applications/`) и бросайте папки на его значок либо
  пользуйтесь пунктом «Открыть с помощью» в файловом менеджере.
- Изображения во вложенных каталогах обрабатываются рекурсивно.
- **В путях допустимы любые символы** — национальные алфавиты, пробелы,
  пунктуация, эмодзи. Это главное отличие от 2.7.

### Параметры командной строки

```
icatalyst [параметры] [каталоги \ файлы]

Параметры:

/png:# режим оптимизации PNG (без чередования):
       1 - уровень сжатия Advanced
       2 - уровень сжатия Xtreme
       0 - пропустить

/jpg:# режим оптимизации JPEG:
       1 - способ кодирования Baseline
       2 - способ кодирования Progressive
       3 - использовать настройки исходного изображения
       0 - пропустить

/gif:# режим оптимизации GIF:
       1 - использовать настройки исходного изображения
       0 - пропустить

"/outdir:#" куда сохранять результат:
       true  - спросить (по умолчанию)
       false - заменить оригиналы оптимизированными
       "полный путь к каталогу" - сохранять в указанный каталог.
       Если каталога нет, он будет создан.

Дополнительные параметры (новые в 3.0):

--verify            сравнивать пиксели PNG до и после (медленно, тщательно)
--strict-lossless   запретить менять RGB под полностью прозрачными пикселями
--threads N         число параллельных задач (0 или без параметра = по числу ядер)
--stream            печатать строки в порядке завершения, а не входных данных
--tsv               машинный вывод вместо таблицы
--doctor            показать найденные инструменты и точные команды
--picker NAME       auto, tk, zenity, kdialog, osascript, terminal или none
--config FILE       использовать этот config.ini вместо Tools/config.ini
--width N           задать ширину таблицы
--no-pause          не ждать нажатия клавиши в конце

Примеры:
icatalyst /gif:1 "/outdir:/home/user/photos" "/home/user/images"
icatalyst /png:2 /jpg:2 "/outdir:true" "C:\images"
```

Если режим не задан в командной строке, Image Catalyst спросит — но только для
форматов, реально присутствующих во входных данных, как это делала версия 2.7.

### Что здесь означает «без потерь»

Пиксели и альфа-канал не меняются никогда, с одним сознательным исключением,
которое было умолчанием ещё в 2.7: `xtreme=/a1` в `Tools/config.ini` разрешает
переписывать **значения RGB под полностью прозрачными пикселями**. Такие пиксели
невидимы, поэтому изображение визуально идентично, но данные пикселей — не
побайтово. Ключ `--strict-lossless` это запрещает.

Замер на 60 уже оптимизированных системных иконках: `--strict-lossless` не стоил
ничего — сжатие оказалось даже чуть лучше (−8,73% против −8,65%), потому что
эвристика «грязной прозрачности» выигрывает не всегда, а гонка кандидатов берёт
меньший результат.

Каждый результат проверяется до того, как будет принят: файл обязан
декодироваться, сохранить размеры и критические чанки и быть **строго меньше**
входа. Иначе оригинал остаётся нетронутым.

### Параметры оптимизации PNG

|Advanced|Xtreme|
|:-------|:----------|
|Структурная оптимизация и один проход deflate. Секунды на изображение.|Исчерпывающий структурный поиск и сжатие класса Zopfli. В 5–15 раз медленнее, на несколько процентов меньше.|

Оба режима считают несколько независимых цепочек наперегонки и берут наименьший
результат, поэтому добавление инструмента может только улучшить итог. Xtreme
гарантированно не даёт файл больше, чем Advanced.

Вывод с чередованием (`Interlaced`) не поддерживается; чередованный исходник
читается корректно и записывается без чередования.

### Параметры оптимизации JPEG

|Baseline|Progressive|
|:-------|:----------|
|Для изображений меньше 10 КБ ([подробнее](http://yuiblog.com/blog/2008/12/05/imageopt-4/))|Для изображений больше 10 КБ ([подробнее](http://yuiblog.com/blog/2008/12/05/imageopt-4/))|

`Default` сохраняет способ кодирования исходника. Оптимизация JPEG — это
преобразование коэффициентов без потерь: `jpegtran` никогда не перекодирует
пиксели заново.

### Различия между платформами, честно

Результат для PNG **не совпадает побайтово между Windows и Linux** и совпасть не
может: TruePNG и DeflOpt — закрытый фриварь только под Windows, аналогов у них
нет. Ни один из результатов не является «правильным»; оба без потерь.

| Шаг | Windows | Linux |
|---|---|---|
| PNG Advanced | TruePNG → DeflOpt → advdef → DeflOpt ‖ oxipng | optipng → advdef ‖ oxipng |
| PNG Xtreme | TruePNG → pngwolf (Zopfli) → DeflOpt ‖ oxipng | optipng → zopflipng ‖ optipng → advdef ‖ oxipng |
| JPEG | `jpegtran` из MozJPEG | `jpegtran` из libjpeg-turbo; MozJPEG по желанию через `make tools-build`, даёт 2–4% на прогрессивных |
| GIF | gifsicle | тот же gifsicle с теми же флагами |
| Диалог выбора каталога | родной диалог Windows | zenity, kdialog или запрос в терминале |

Знак `‖` означает, что цепочки считаются наперегонки и побеждает меньший файл.

### Config.ini

`Tools/config.ini` сохранил все ключи версии 2.7 — существующие настройки
работают без правок. Новые необязательные ключи: `profile`
(`auto`/`windows`/`posix`), `timeout`, `picker`, `preserve_mtime`,
`xtreme_iterations`, а также платформенно-нейтральные аналоги строк флагов
TruePNG (`gamma`, `keep_colortype`, `keep_bitdepth`, `keep_palette`,
`advanced_dirty_transparency`, `xtreme_dirty_transparency`). Ключи
`pngtags`/`jpegtags`/`giftags` дополнительно принимают значение `keep-icc`,
сохраняющее цветовые профили, которые `true` удалил бы.

Программа никогда не перезаписывает этот файл.

### Переход с 2.7

Обе реализации пока лежат рядом. `iCatalyst.bat` — это по-прежнему версия 2.7, и
она работает; новое ядро вызывается как `python3 -m icatalyst`, а под Windows —
через `iCatalyst-3.bat`. Legacy-файлы будут удалены только после того, как работа
`parity-windows` в CI подтвердит на настоящих бинарниках, что новое ядро сжимает
не хуже.

Изменения в поведении, о которых стоит знать:

- Пути с любыми символами теперь работают. В 2.7 каталог с именем `Фото — копия`
  молча терял всё своё содержимое, потому что длинного тире нет в cp866.
- Счётчик циклов GIF выживает при удалении метаданных. В 2.7 `giftags=true`
  передавал gifsicle `--no-extensions`, тот выбрасывал расширение NETSCAPE, и
  бесконечно циклящийся GIF становился одноразовым.
- Прерывание по Ctrl-C происходит немедленно и никогда не оставляет обрезанный
  файл.
- Два входных файла с одинаковым именем больше не затирают друг друга в
  выходном каталоге.
- Время изменения файлов сохраняется по умолчанию (`preserve_mtime=false`
  возвращает прежнее поведение).
- Пакетный запуск без `/outdir` и без терминала, в котором можно спросить, теперь
  останавливается с ошибкой, а не перезаписывает оригиналы молча.

### Дополнительно

- По умолчанию оптимизация идёт параллельно, по одной задаче на ядро. Изменить —
  ключом `--threads N` или `thread` в `config.ini`. Замер на 16 ядрах:
  177 с → 38 с при побайтово одинаковом результате.
- Чтобы приостановить работу под Windows, щёлкните правой кнопкой в окне консоли
  и выберите «Выделить всё»; для продолжения щёлкните снова.

### Сборка

Чтобы пользоваться Image Catalyst из исходников, собирать ничего не нужно — это
обычный Python. Цели сборки существуют для создания распространяемых артефактов:

```
make deb        # пакет .deb, проверенный lintian
make binary     # самодостаточный бинарник для Linux (Python для запуска не нужен)
make exe        # iCatalyst.exe (только Windows)
make tools      # скачать готовые оптимизаторы, сверив их SHA-256
make test       # весь набор тестов; проходит и без установленных оптимизаторов
```

`make binary` и `make exe` используют PyInstaller — это зависимость **времени
сборки**, самой программе не нужно ничего, кроме стандартной библиотеки. На
Ubuntu 24.04 и новее PEP 668 запрещает установку в системный Python, поэтому
`make binary` создаёт собственное виртуальное окружение.

GitHub Actions собирает всё это по тегу, но **только после** того, как прошли
тесты и харнесс паритета с 2.7: приложить к релизу пакет, собранный из заведомо
сломанного кода, — худшее, что здесь может случиться. Релиз создаётся черновиком,
чтобы перед публикацией можно было взглянуть на состав.

| Артефакт | Для кого |
|---|---|
| `icatalyst_<версия>_all.deb` | Debian, Ubuntu, Mint — ставит команду, пункт меню, man-страницу и подтягивает оптимизаторы через `apt` |
| `iCatalyst-<тег>-linux-x86_64.tar.gz` | другие дистрибутивы или запуск без установки |
| `iCatalyst-<тег>-windows-x86_64.zip` | Windows: `iCatalyst.exe` и вложенные оптимизаторы рядом с ним |
| `iCatalyst-tools-linux-x86_64.tar.gz` | готовые сборки MozJPEG, pngwolf и oxipng, чтобы не компилировать |
| `third-party-sources.tar.gz` | исходники GPL-компонентов, как требуют их лицензии |
